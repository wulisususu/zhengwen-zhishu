# 公文结构化生成与版式渲染（gongwen）

按 GB/T 9704-2012《党政机关公文格式》生成 Word 公文。

核心思路是**把「写什么」和「排成什么样」拆开**：

```
表单字段 ──┐
          ├─→ GongwenDoc(IR) ─→ renderer ─→ DOCX（版式由代码保证）
模型正文 ──┘         │
                    └─→ checker ─→ 校核意见（只提示，不改稿）
```

模型只负责正文语义，标题、主送机关、发文字号、署名、成文日期这些结构字段来自表单。
这样即使模型输出不稳定，成文的版式仍然是确定的、可复现的。

---

## 1. IR 示例

```json
{
  "doc_type": "通知",
  "title": "XX市政务服务管理局关于加强政务服务中心窗口作风建设的通知",
  "recipients": ["各县（市、区）政务服务管理局", "局属各单位"],
  "issuer_org": "XX市政务服务管理局",
  "signer_org": "XX市政务服务管理局",
  "sign_date": "2026年10月24日",
  "doc_number": "X政服发〔2026〕12号",
  "secret_level": "",
  "urgency": "",
  "signer_name": "",
  "body": [
    { "text": "为深入贯彻……，现就有关事项通知如下。", "level": 0 },
    { "text": "一、提高思想认识", "level": 1 },
    { "text": "（一）规范服务行为。……", "level": 2 },
    { "text": "1. ……", "level": 3 },
    { "text": "特此通知。", "level": 0 }
  ],
  "attachments": ["XX工作方案"],
  "cc": ["市委办公室"],
  "note": "",
  "print_org": "XX市政务服务管理局办公室",
  "print_date": "2026年10月25日"
}
```

`level` 含义：0 普通段落，1 一级标题（一、），2 二级标题（（一）），3 三级标题（1.）。

## 2. 字段 → 版式位置

| IR 字段 | 版式位置 | 字体 / 字号 |
|---|---|---|
| `copy_no` | 版心左上第一行（份号） | 黑体 3 号 |
| `secret_level` | 份号下一行（密级） | 黑体 3 号 |
| `urgency` | 密级下一行（紧急程度） | 黑体 3 号 |
| `issuer_org` | 发文机关标志（红头），居中、红色 | 小标宋 26pt |
| `doc_number` | 发文字号，居中 | 仿宋 3 号 |
| `signer_name` | 上行文时标注于发文字号右侧 | 仿宋 3 号 |
| — | 红色分隔线，与版心等宽 | 1.5pt 红线 |
| `title` | 标题，居中，分隔线下空二行 | 小标宋 2 号 |
| `recipients` | 主送机关，标题下空一行、左侧顶格，末尾全角冒号 | 仿宋 3 号 |
| `body[level=1]` | 一级标题 | 黑体 3 号 |
| `body[level=2]` | 二级标题 | 楷体 3 号 |
| `body[level=3]` | 三级标题 | 仿宋 3 号 |
| `body[level=0]` | 正文，首行缩进 2 字符 | 仿宋 3 号，固定行距 28.8pt |
| `attachments` | 附件说明，正文下空一行、左空 2 字 | 仿宋 3 号 |
| `signer_org` | 发文机关署名，右空 2 字 | 仿宋 3 号 |
| `sign_date` | 成文日期，署名下一行、右空 4 字 | 仿宋 3 号 |
| `note` | 附注，左空 2 字，加圆括号 | 仿宋 3 号 |
| `cc` | 版记·抄送机关，左空 1 字 | 仿宋 4 号 |
| `print_org` / `print_date` | 版记·印发机关（左）与印发日期（右） | 仿宋 4 号 |
| — | 页码，单页右空 1 字、双页左空 1 字 | 宋体 4 号 |

## 3. 页面参数

| 项 | 值 |
|---|---|
| 纸张 | A4（210 × 297 mm） |
| 页边距 | 上 37 / 下 35 / 左 28 / 右 26 mm |
| 版心 | 156 × 225 mm |
| 正文 | 3 号仿宋，每面 22 行、每行 28 字，固定行距 28.8 磅 |

## 4. 校核规则

**结构层**（`schema.validate`）

- 文种必须在支持范围内（通知 / 请示 / 报告 / 函 / 纪要）
- 标题非空；标题不用逗号句号等标点；标题过长提示
- 主送机关必填（通知、请示、报告、函）；**请示不得多头主送**
- 成文日期格式须为「2026年10月24日」
- 发文字号须为「机关代字〔年份〕序号号」，年份用六角括号
- **报告中不得夹带请示事项**（检测「请批复」「妥否」等）
- 上行文（请示 / 报告）建议标注签发人
- 正文提到「附件」但无附件说明时提示

**内容层**（`checker`）

- 一级标题序号连续性（一、二、三 不跳号）
- 各文种惯用结尾语（特此通知 / 以上请示，请批复 / 特此报告 / 特此函告）
- 半角括号序号、重复标点
- 模糊时间表述（今年、去年、近期）
- 称谓混用（贵单位 / 你单位）
- 单段超过 400 字提示分条
- 标题是否以文种结尾

校核只输出 `error / warn / info` 三级意见，**不改动文稿**——改稿权始终在人手上。

## 5. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/gongwen/meta` | 文种、密级、紧急程度、字段说明 |
| POST | `/api/v1/gongwen/draft` | 表单 → IR + 校核结果 |
| POST | `/api/v1/gongwen/check` | 已有 IR → 重新校核 |
| POST | `/api/v1/gongwen/render` | IR → DOCX（`Content-Disposition` 带文件名） |

`draft` 返回的 `meta.generated_by` 取值：

- `llm`：模型一次生成成功
- `llm_repaired`：模型首轮只给了标题，补写后合格
- `template`：模型输出不可用，退回骨架稿（明确标注，不冒充模型输出）

---

## 6. 已知限制

- **印章**不做渲染：电子印章需另行加盖章图片，纸质件由用印环节处理。
- **版记位置**跟随正文末尾，不强制压到版心下边缘（Word 分页由排版引擎决定）。
- **标题回行**不做「词意完整、排列对称」的自动优化，长标题需人工断行。
- **字体**：DOCX 内只写入字体名（方正小标宋简体 / 仿宋_GB2312 / 楷体_GB2312），打开文档的机器需装有对应字体，否则会被 Word 替换为相近字体。
