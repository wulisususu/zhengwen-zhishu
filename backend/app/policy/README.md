# 政策库与政策解读（policy）

面向「政策解读」业务的一组能力：**把政策当有生命周期的对象管理**，再在此之上做条款级检索与有据问答。

不替换现有 RAG 框架，也不新增大依赖；只在业务层补上政策特有的那层结构。

```
上传原文 ─→ 解析（逐页 + 条款切分 + 页码 + 校验值）
              ↓
         元数据 + 生命周期（文号/机关/生效失效/状态/替代关系）
              ↓
         条款级检索（BM25 + 覆盖率 + 答案类型）
              ↓
         有据问答（结论必须带 [n]；依据不足不生成结论）
```

---

## 1. 数据模型

### policy_documents（政策文件）

| 字段 | 说明 |
|---|---|
| `title` / `doc_no` / `issuer` | 标题、文号、发文机关 |
| `source_url` | 原始来源链接（结论回溯用） |
| `region` / `target_audience` / `theme` | 地区、适用对象、政策主题 |
| `publish_date` / `effective_date` / `expire_date` | 发布、生效、失效日期（统一存 `YYYY-MM-DD`） |
| `status` | 现行有效 / 已废止 / 已修订 / 待核实 / 尚未生效 |
| `supersedes` / `superseded_by` / `revision_of` / `version` | 替代关系与版本链 |
| `file_name` / `file_path` / `page_count` / `clause_count` / `char_count` | 原文与规模 |
| `checksum` | 全文校验值（去空白后 sha256 前 32 位），用于判重与防篡改 |
| `review_note` | 待核实说明 / 人工核实备注 |

### policy_clauses（条款，引用与解读的最小单位）

| 字段 | 说明 |
|---|---|
| `policy_id` / `seq` | 所属政策、全文顺序 |
| `clause_no` | 「第六条」 |
| `chapter` | 所属章，如「第二章 申请与条件」 |
| `heading` | 条款首句摘要 |
| `content` | 条款原文（不含章节标题） |
| `page` | **起始页码**（PDF 真实页码） |
| `char_start` / `char_end` | 在全文中的字符区间，供原文定位 |
| `checksum` | 条款校验值 |
| `search_text` | 归一化检索文本 |

### policy_qa_logs（问答留痕）

问、答、引用条款 JSON、范围、是否无依据、生成方式、模型、反馈。**任何一个结论都能回溯到当时的条款与模型输出。**

## 2. 状态是推导出来的，不是随便填的

`lifecycle.derive_status()` 规则：

1. 显式状态优先；
2. 但若显式写了「现行有效」而 `expire_date` 已过 → 判为「已废止」（以日期为准）；
3. 无显式状态时：`expire < 今天` → 已废止；`effective > 今天` → 尚未生效；有替代文件 → 已修订；否则现行有效。

`lifecycle.lifecycle_issues()` 输出元数据体检：缺文号 / 缺机关 / 缺来源链接 / 失效早于生效 / 已废止但未注明替代文件 / 状态待核实。这些直接展示在入库结果里，让经办人当场补。

## 3. 条款切分

- 主规则：行首「第X条」；章节标题（第X章/节）只用于归属，**不并入条款正文**。
- 降级一：识别不到「第X条」时按「一、二、」切（规划、方案类文件的主结构）。
- 降级二：若「一、」之下还有「（一）（二）」，**继续细分为「三、（一）」这样的引用单元**。
  规划类文件没有「第X条」，一整节两千字；不细分则引用会连着一大段原文，
  既定位不准、也无法高亮，而汉语公文引用本就习惯写到「三、（一）」。
- 降级三：仍无编号时按空行分块，并写入 `parse_warnings`。
- 页码：多页拼成全文时记录「字符偏移 → 页码」映射，条款起始偏移换算为页码。

### 三种入库通道

| 通道 | 适用 | 说明 |
|---|---|---|
| 上传文件 | 有文字层的 PDF / DOCX / TXT | 直接提取，1 秒级 |
| 上传文件（自动 OCR） | 扫描件、网页截图打印件 | 无文字层时按 200dpi 渲染逐页 OCR，按行距与缩进合并成段落；入库时回传 `ocr_used=true` 并提示核对条款编号与数字 |
| 粘贴正文 | 网页政策、OCR 质量不足 | `POST /policy/documents/text`，文字最干净，推荐用于演示 |

OCR 依赖 `rapidocr-onnxruntime`（CPU 即可，中文识别无需联网）。未安装时上传扫描件会返回明确错误，
提示「安装 OCR 组件或改用粘贴正文」，不会再静默入库空壳。

条款切不出来时，接口除了报错还会回传**已识别的字数、页数与开头 120 字**，
让人能判断是「文件本身没内容」还是「编号规则没匹配上」。

## 4. 检索打分

```
raw   = 0.50 × BM25(饱和归一) + 0.30 × 查询词覆盖(idf 加权) + 0.20 × 答案类型匹配 − 目的条款惩罚
score = min(1, raw / 0.70)        # 校准，使 0.60 附近意味着「强相关」
```

三个信号各自解决一个问题：

| 信号 | 解决的问题 |
|---|---|
| BM25 + 覆盖率 | 条款很短，词汇重合度就是最强的相关性信号 |
| 答案类型匹配 | 「补贴比例是多少」需要的是含百分比的条款，不是「制定本办法」那一条 |
| 目的条款惩罚 | 询问具体数值/时限时，「为…制定本办法」「本办法适用于」几乎不可能是答案 |

全过程可拆解：接口返回 `score / bm25 / coverage / matched_terms`，能解释「为什么召回这一条」。

## 5. 有据问答的三条硬规则

1. **只依据检索到的条款作答**，每句结论必须带 `[n]`；没有引用标记的输出直接作废，退回原文摘录。
2. **最高分低于阈值不生成结论**，只把候选条款与分数如实列出（界面显示「未找到足够依据」）。
3. **已废止条款不进结论**，只能出现在「补充说明 / 历史对照」里并显式标注；除非显式允许。

额外的两道闸门：

- **库外问题闸门**：问题实义词在政策库中的覆盖率 < 35% 时判定为库外问题，不生成结论，避免用无关条款拼凑答案。
- **模型拒答识别**：模型明确表示「未作规定」时转为无依据，而不是硬写一段。

返回结构（`POST /policy/qa`）：

```json
{
  "status": "answered | no_basis",
  "sufficient": true,
  "sufficiency": "full | partial",
  "conclusion": "… [1] …",
  "supplement": "…",
  "manual_confirm": ["待人工确认：…"],
  "citations": [{
    "index": 1, "policy_title": "…", "doc_no": "…", "issuer": "…",
    "clause_no": "第六条", "content": "…", "page": 1, "status": "现行有效",
    "excerpt": { "pre": "…", "hl": "命中所在整句", "post": "…" }
  }],
  "candidates": [{ "clause_no": "…", "score": 0.54, "below_threshold": true }],
  "meta": { "candidates": 8, "cited": 1, "excluded_deprecated": 0,
            "threshold": 0.6, "generated_by": "llm | extractive | none" }
}
```

`generated_by` 如实标注：`llm` 模型生成、`extractive` 模型不可用退回原文摘录、`none` 未生成。**不把摘录冒充模型输出。**

## 6. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/policy/documents` | 上传原文（multipart），解析入库 |
| GET | `/policy/documents` | 列表（状态 / 关键词筛选） |
| GET | `/policy/documents/{id}` | 详情（含全部条款与体检） |
| PATCH | `/policy/documents/{id}` | 补录/修正元数据，改日期会重算状态 |
| DELETE | `/policy/documents/{id}` | 删除政策及条款 |
| POST | `/policy/search` | 条款级检索（只召回，不下结论） |
| POST | `/policy/qa` | 政策问答（有据才答，带引用） |
| GET | `/policy/qa/logs` | 问答留痕（审计） |
| GET | `/policy/stats` | 政策数 / 条款数 / 各状态分布 / 问答量 |

前端页面：`/policy`（政策库 + 问答 + 原文详情抽屉），支持把引用条款「加入公文起草依据」。

## 7. 已知限制与后续

- **纯词法检索的边界**：同义表述（「贴息比例」vs「按百分之五十给予」）依赖答案类型信号兜底；接入 bge-small 后建议改为 BM25 召回 + 向量重排（`data/kb/models` 目前为空）。
- **PDF 无页眉页脚/附件识别**：只提取正文文字；表格按单元格拼行，复杂表格建议先转 DOCX 或 MinerU。
- **条款层级**：目前以「条」为最小单位，「款/项」并入所属条；如需精确到「（一）」需扩展 `policy_clauses.level`。
- **印章/发文日期**：不解析，属版式信息，由公文模块负责。
