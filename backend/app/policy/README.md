# 政策问答（policy）

在既有政策库（T1）之上做**条款级检索与有据问答**。本包不另建政策表、不另做原文解析，
政策资料只有一处。

```
/gov/policies/import（审核人）─→ T1 抽取（PDF 走 T3 逐页解析 + OCR，缺页或 OCR 不完整则不入库）
                                   ↓
                             policy.db：政策 + 条款（导入后一律「待核实」）
                                   ↓
/gov/policies/{id}/verify（审核人）人工核验：现行 / 已废止，补录生效、失效日期
                                   ↓
corpus.load ─→ 条款级检索（BM25 + 覆盖率 + 答案类型）─→ 有据问答（结论必须带 [n]）
```

---

## 1. 能否作为现行依据

状态只来自人工核验（T1 的 `verified_status`），`corpus.effective_status` 再按日期纠偏：

| 核验结果 | 日期 | 问答中的状态 | 可作现行依据 |
|---|---|---|---|
| 未核验 | — | 待核实 | 否 |
| 已废止 | — | 已废止 | 否（只作历史对照） |
| 现行 | 已过失效日期 | 已废止 | 否 |
| 现行 | 未到生效日期 | 尚未生效 | 否 |
| 现行 | 在有效期内 | 现行有效 | 是 |

缺文号、机关或来源不会让政策自动成为现行依据；只有审核人核验后才可以。

## 2. 引用编号

每条引用带 `citation_id`（`clause:<条款 id>`），与 `/gov/citations/batch` 及文稿 `citationIds` 同一格式，
问答引用可以直接带入起草，不需要另一套编号。

## 3. 检索打分

```
raw   = 0.50 × BM25(饱和归一) + 0.30 × 查询词覆盖(idf 加权) + 0.20 × 答案类型匹配 − 目的条款惩罚
score = min(1, raw / 0.70)        # 校准，使 0.60 附近意味着「强相关」
```

| 信号 | 解决的问题 |
|---|---|
| BM25 + 覆盖率 | 条款很短，词汇重合度就是最强的相关性信号 |
| 答案类型匹配 | 「补贴比例是多少」需要的是含百分比的条款，不是「制定本办法」那一条 |
| 目的条款惩罚 | 询问具体数值/时限时，「为…制定本办法」「本办法适用于」几乎不可能是答案 |

只有标题的「序言」不参与检索（标题含全部检索词，会排在真正作答的条款前面）。
BM25 的词权重依赖语料规模：库里只有一两份小政策时分数整体偏低，属于预期。

## 4. 有据问答的规则

1. **只依据检索到的条款作答**，每句结论必须带 `[n]`；没有引用标记的输出作废，退回原文摘录。
2. **最高分低于阈值不生成结论**，只列出候选条款与分数。
3. **已废止、待核实、尚未生效的条款不进结论**；已废止条款只作历史对照（除非显式允许）。
4. **库外问题闸门**：问题实义词在政策库中的覆盖率 < 35% 时不生成结论。
5. **模型拒答识别**：模型明确表示「未作规定」时转为无依据。

模型调用经 `llm_chat`，遵守 `model.mode`（offline / intranet / cloud_allowed）；被拒绝或不可用时退回原文摘录，
`meta.generated_by` 如实标注 `llm` / `extractive*` / `none`，不把摘录冒充模型输出。

## 5. 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/policy/search` | 登录 | 条款级检索（只召回，不下结论） |
| POST | `/policy/qa` | 登录 | 政策问答（有据才答，带引用） |
| POST | `/policy/qa/stream` | 登录 | 同上，SSE：先给证据再逐块输出，`final` 为准 |
| GET | `/policy/qa/logs` | 登录 | 问答留痕：审核人看全部，其他人只看自己的 |

政策列表、详情、统计、导入与核验：用 `/gov/policies`（见 `backend/docs/policy-api.md`）。

## 6. 已知限制

- **纯词法检索的边界**：同义表述依赖答案类型信号兜底；接入向量模型后可改为 BM25 召回 + 向量重排。
- **条款层级**：以 T1 切分的条款为最小单位。
- **每次问答读取全部现行条款打分**：政策规模在数百份以内没有问题，更大时需要建倒排索引。
