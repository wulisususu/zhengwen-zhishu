## 方案选择

采用现有 Vue 3 + Pinia + FastAPI + SQLite，在 GovOfficeAdapter 契约下新增 HTTP 实现，后端增加政务文稿和审核业务。

考虑过直接复用旧聊天页面承载政务流程，但它没有政务文稿、送审、审核和版本状态，无法满足本次方向；也考虑过重写前后端，但会重复已有认证、文件和文档服务。本方案保留现有页面和服务，补齐真实的数据流。

## 本期目标与顺序

### 第一阶段：先跑通不依赖模型的真实闭环

1. 登录后默认进入 /gov，保留原有路由和旧功能入口。
2. 显示真实登录身份；生产环境不允许用演示身份切换获得权限。
3. 新建文稿，编辑标题、文种、正文、主送机关、发文机关、承办人和日期；保存到后端。
4. 文稿列表和详情读取数据库；刷新或重启测试服务后内容仍存在。
5. 上传真实材料、关联到文稿；复用现有文件权限与解析状态，移除关联不等于删除原文件。
6. 送审、退回、再次编辑和提交、审核通过；操作记录写入数据库。
7. 生成真实 DOCX 并鉴权下载；明确区分内部草稿与审核状态，修正此链路的 A4 页面和页边距。

### 第二阶段：接通已有模型能力

在第一阶段通过后复用已有生成服务，接入“生成初稿”和任务状态。实际模型不可用时返回明确错误，不使用演示答案冒充生成结果。只有真实模型请求成功且产物可下载，才将模型联调列为通过；测试替身结果单独记录。

## 权限与状态的拟定规则

以下为实施建议，需用户确认方案，不表示用户已经指定这些映射：

- 普通用户映射为起草人；管理员可起草并审核他人的稿件；禁止任何人审核自己的稿件。
- 起草人默认只能查看和修改自己的文稿；管理员可查看送审材料并审核。
- 草稿/退回状态允许作者修改；审核中/审核通过状态禁止直接编辑。
- 非法状态流转由后端拒绝，不依赖前端隐藏按钮；并发修改使用版本号检测，避免覆盖。
- 审核通过表示人工审核流程完成，不得伪装成自动审校已经通过。
- 本期不自动给管理员授予正式发文权限；canFormalIssue 默认 false。正式发文导出维持禁用，内部草稿真实下载先验收。
- 未实现的政策检索和自动审校能力明确返回未接入状态。不得把空问题列表当作“已检查无问题”。

## 数据与接口边界

- 复用现有 users、files、JWT、认证依赖和错误信封。
- 新增 gov_documents（所有者、文种、状态、版本、文稿结构 JSON、时间）、gov_document_materials（文稿和文件关联）、gov_review_records（实际操作人与动作记录）。
- 文稿结构沿用 OfficialDocument/DocBlock/DocSegment，保留稳定的块和片段 ID。
- 新政务接口放在 `/api/v1/gov` 下，以文稿 CRUD、材料关联、审核动作和导出为边界；实现前在接口契约中确定字段和错误码。
- 政务配置、身份和运行状态来自后端；Mock 仅保留给显式演示模式与测试，生产请求失败时不得悄悄回退 Mock。
- 导出增加鉴权下载信息，补全现有 ExportResult，前端实际下载 Blob，而非只显示“导出成功”。
- 运行与测试使用独立数据库和文件目录，不写入其他工作区数据，不重启其他项目的服务。

## 验收要求

- 两个真实测试账号完成：登录 → 新建 → 编辑 → 保存 → 刷新恢复 → 上传材料 → 送审 → 退回 → 修改重提 → 他人审核 → 下载真实内部草稿。
- 确认请求抵达真实 FastAPI、数据进入隔离 SQLite；浏览器测试不得用假 token 或 Mock 代替该验收。
- 用未登录、跨用户、作者自审、重复提交、过期版本、审核中修改、未经授权下载等用例验证后端边界。
- 模型不可用、文件解析失败、导出失败明确反馈，不能展示成功状态。
- 检查实际 DOCX 的 OOXML 页面参数、正文和水印；对导出样本进行渲染检查。
- 旧版认证、文件与文档相关测试回归；PPT 等旧页面保留构建与路由检查，真实模型验收与静态回归分别说明。
