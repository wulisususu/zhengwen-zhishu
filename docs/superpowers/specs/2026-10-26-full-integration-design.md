# T2 T3 與完整業務整合

依使用者明確要求執行第4至6步，以已部署的 T1 / 基礎聯調 349d082 為基線，在下一階段總整合分支逐批整合。完成各門檻才合 main，不 push。

## 已選方向與約束

沿用真實 JWT、SQLite、政策來源與版本機制，接入既有 T2 和 T3；不另建平行的文稿資料流。直接將各任務分支互相合併會混入尚未驗證的執行路徑；因此先保存原交付，再在總整合分支接線並驗證。

通知增加可持久化的發文字號、版記、附注及表格。從同一份後端文稿生成審校輸入與 DOCX；保留段落/欄位真實 id。審校結果與文稿 version 綁定，修改後失效。批准時重新審校；嚴重錯誤或工具不可用不能當作通過。保存、送人工審核及內部草稿導出仍可用。正式發文維持禁止。其他文種保留原流程並明示 T2 僅覆蓋通知。

政策引用由後端讀取政策庫狀態，不能採信瀏覽器回傳的政策有效性。舊引用失效或政策庫故障須可見。內部 DOCX 仍含來源與未核驗標記。

T3 先在實際 RK3588 測相同 jar、官方文字/掃描 PDF、50頁合成樣本、表格、失敗與超時。門檻：每頁平均不超過3秒、峰值常駐記憶體不超過1.5GB，頁碼與表格結構可用。文字 PDF 才用 OpenDataLoader；無文字層或適配器失敗走既有 pdftotext / MiniCPM 路徑。政策 PDF 使用明確輸入標題及來源，忽略 PDF title 元資料；中文換行空白規範化須保留來源可追溯。

使用者已確認 WPS 實機驗收即可。樣張須實際打開/輸出並逐頁目視驗證，不能以 OOXML 檢查或 LibreOffice 冒充。如缺 WPS 環境，保留整合分支，不宣稱總驗收或合 main 完成。

## 資料與部署

維持原帳號、資料庫、模型出口及 OCR 服務。候選版本先使用資料副本與獨立政策庫驗證；部署前 SQLite backup、配置備份及原子切換，失敗回退不覆蓋新增業務資料。Windows 分批提交並產生可恢復 bundle。
