# 政策问答放开：会对话、围绕政策库作答

日期：2026-10-27。来源：`docs/測試疑問.md`（2026-10-27 两节）与用户的场景描述。

## 背景

现在的政策问答只认「检索命中已核验现行条款」这一种情况，其余一律显示「未找到足够依据，不生成结论」：

- 政策库 101 份文件全部待核实，默认范围下可用条款为 0，任何问题都被拒答；
- 切到「全部政策（含待核实）」也被拒答，因为待核实政策在任何范围下都不能作依据；页面上「可选择含待核实试查」的提示是误导；
- 「你好」「我想了解某个政策」直接进检索，同样被拒答；
- 拒答原因一律套「最高相关度未达阈值」，出现过「最高相关度 0.87，未达到可信阈值 0.60」这种自相矛盾的说法；
- 每次提问互相独立，追问时系统不知道上一句说的是哪份政策。

## 用户场景

文员会先打招呼（「你好」），再说「能帮我看看某某政策吗」，中途可能问到和政策无关的事（「电脑命令行怎么操作」）。

## 规则

1. **打招呼、寒暄**：正常、自然地回应，说明能做什么，给一两个问法示例。
2. **政策问题一律依据政策库**：
   - 命中已核验现行条款：按现在的方式直接回答，带 [n] 引用；
   - 只命中待核实条款：照样回答，但回答开头由**后端固定加上**这句前提（不交给模型写）：
     「以下内容来自已入库但尚未经人工核验的政策，仅供参考；正式引用前，请审核人在政策库完成核验。」
     引用卡片照旧显示「待核实」；
   - 已核验和待核实都命中时，只用已核验的作答，待核实的在「待人工确认」里列出（现有行为）；
   - 已废止、尚未生效的条款照旧不作为依据；
   - 库里找不到相关内容：说明政策库暂未收录，**不得凭模型自身知识陈述任何政策内容、文件名、文号或数字**。
3. **「帮我看看某某政策」按政策名称匹配**：唯一匹配时介绍这份政策的要点（带引用）；多份相近或匹配不上时反问，并列出名称相近的几份供点选。
4. **和政策无关的问题**：友好说明这里专门解答政策问题，建议咨询信息部门或相关专业人员；**不给出具体步骤、命令或答案**；措辞自然，不每次都是同一句。
5. **多轮上下文**：带上最近 3 轮问答，追问（「那补贴多少」）能接上前文。
6. **模型不可用**：用几句轮换的固定话术兜底，不显示「已检索 0 条」。

## 不变的部分

- 已核验现行条款的作答、引用、数值直引原文、模型输出质检全部保持现状；
- 政策状态仍然只来自人工核验；本次不做批量核验；
- 加入公文起草依据时，待核实条款照旧以「未核验」状态进入文稿，由起草页现有的核验提示把关。
