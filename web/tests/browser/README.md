# 浏览器检查（政务办公工作台 `/gov/*`）

在真实浏览器里检查三种桌面分辨率：1280×800、1440×900、1920×1080。

## 运行

```bash
cd web
npm ci                 # 首次
npm run test:browser   # 先构建，再检查
```

只检查已有的 `dist/`，跳过构建：

```bash
node tests/browser/run.mjs
```

Windows PowerShell 命令相同。脚本按以下顺序查找浏览器：

1. 环境变量 `CHROME_PATH` 指定的路径；
2. 本机安装的 Chrome；
3. Edge（Windows 自带）。

如需指定浏览器：

```powershell
$env:CHROME_PATH = "C:\Program Files\Google\Chrome\Application\chrome.exe"
npm run test:browser
```

不需要后端：`/gov/*` 页面只走前端的 Mock 适配器，脚本用 `vite preview` 提供构建产物。

## 检查内容

| 文件 | 内容 |
|---|---|
| `layout.mjs` | 每个页面：无横向溢出；按钮与输入框没有被裁出视口；按钮文字没有被挤压；关键按钮完整可见且没有被其他元素遮挡；A4 预览按 794×1123 真实尺寸排版、缩放后能完整放进预览区。弹窗（导出、提交审核、添加材料、申请例外、审核记录、审核通过确认）：位于视口内、按钮可点且没有被遮挡、打开后焦点在弹窗内、Esc 能关闭。 |
| `flows.mjs` | 默认身份为 `demo_drafter`；没有「离线 / 数据不出本机」字样；严重问题没有「忽略」按钮；采纳建议后 A4 正文同步更新；「去填写」能聚焦字段，填写后替换【待补充】；「定位」能把 A4 预览滚动到对应位置并高亮；AI 严重问题必须人工复核且必须填写理由；例外申请仍然阻断审批；正式导出被禁用；内部草稿不会假装已生成文件；提交审核后编辑锁定；起草人不能审核；切换为 `demo_reviewer` 后，有严重问题时不能通过、批准例外会留痕、退回必须填写意见、操作记录在审核人名下；审核人不能编辑文稿；起草人能看到审核结果与意见；审核通过的流程；政策问答的引用详情、无依据状态、新问题不会编造回答、面板可收起。 |

## 输出

检查结果输出到 `tests/browser/shots/`，该目录已加入 `.gitignore`，不会提交：

- `report.json`：每项检查的结果；
- `<分辨率>/*.png`：各页面截图，以及定位、引用详情、退回后记录、导出弹窗的截图。

有检查失败时，退出码为 1，并在末尾列出失败项。
